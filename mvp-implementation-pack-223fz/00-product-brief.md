# Product brief

## Назначение

Operational Workspace для поставщика по 223-ФЗ - это рабочий кабинет, который помогает команде поставщика ежедневно управлять закупками: находить, оценивать, готовить, отслеживать и закрывать участие.

MVP не должен конкурировать с ЕИС, ЭТП или аналитическими системами полного цикла. Его ценность в операционной дисциплине: меньше пропущенных дедлайнов, меньше хаотичного чтения PDF, быстрее решение `bid / review / no-bid`.

## Целевой пользователь

Основной пользователь MVP - владелец или менеджер малого/среднего поставщика, который:

- ищет закупки по нескольким регулярным правилам;
- вручную читает документацию;
- боится пропустить изменения, разъяснения и сроки подачи;
- принимает участие не во всех закупках, а только в подходящих;
- работает без тяжелой тендерной CRM.

## Основные сценарии

### 1. Настроить watchlist

Пользователь задает ключевые слова, исключения, регионы, диапазон цены, OKPD2, заказчиков allow/block list, горизонт дедлайнов и флаги вроде `onlyWithSecurity`.

Результат: система регулярно ищет совпадения и показывает, почему конкретная закупка попала в выдачу.

### 2. Открыть нормализованную карточку

Пользователь видит номер закупки, заказчика, цену, дедлайн, способ закупки, документы, требования, изменения, source freshness, текущий системный этап и внутренний этап работы.

Результат: карточка заменяет хаотичный набор вкладок, PDF и заметок.

### 3. Принять bid/no-bid решение

Система считает rule-based score:

- fit: 0-30;
- economics: 0-20;
- execution risk: 0-20;
- compliance risk: 0-20;
- urgency: 0-10.

Hard blockers всегда сильнее общей суммы баллов. Если confidence ниже 60, итог не может быть `BID`, только `REVIEW` или `NO_BID`.

### 4. Провести закупку через воронку

Внутренние стадии:

`INBOX -> QUALIFY -> GO -> PREPARE -> SUBMITTED_EXTERNALLY -> WON / LOST -> ARCHIVED`

Внутренняя стадия не равна системному этапу ЕИС. Например, закупка может быть `COMPLETED` у источника, но оставаться `LOST` или `ARCHIVED` во внутреннем процессе.

### 5. Получать алерты

События MVP:

- `new_match`;
- `deadline_t48`;
- `deadline_t24`;
- `deadline_t2`;
- `new_change`;
- `new_clarification`;
- `stage_sla_breach`.

Сообщение короткое: номер, заказчик, событие, дедлайн, ссылка в карточку. Вложения и чувствительные данные в Telegram/email не отправлять.

### 6. Получить AI-summary

AI извлекает только факты из текста документации, изменений, разъяснений и протоколов. Каждый факт должен иметь `source_spans`. Если данных нет, AI возвращает `unknowns`, а не придумывает ответ.

## Не входит в MVP

- полная историческая аналитика по всем закупкам;
- ML-прогноз победы;
- глубокая ERP-модель компании;
- реестр договоров как полноценный модуль;
- планы закупок как основной источник;
- автоматическая подача заявки на ЭТП;
- юридически значимое заключение без проверки человеком.

## MVP-метрики

- Пользователь создал хотя бы один active watchlist.
- На контрольной выборке из 20 закупок корректно заполнены цена, заказчик, дедлайн, документы и source stage.
- На тестовом наборе не менее 90% алертов отправляются без дублей.
- AI на выборке 10-15 закупок извлекает дедлайны, обязательные документы и 3-5 meaningful risks без галлюцинаций.
- Пользователь может пройти полный путь: watchlist -> карточка -> score -> kanban -> alert -> AI-summary.
